## Questions and criteria (decision record §4.1)

- **X-02** — Does the player-side overlap remove the visible and audible seam? Today versus AUD-02 in headless Chromium with session A clips; an offline "played mix" of 20 seams. *Success:* luminance dip ≤ 5 %; 0 reloads on `playing`; swap p95 ≤ 50 ms; seam level step ≤ 12 dB median and ≤ 25 dB p90; 0 onset clicks.
- **X-13** — Which ceiling? −18 versus −20 LUFS on session A's 63 clips, offline; listening H2. *Success:* narrated-to-next step ≤ 14 LU median; 0 true-peak overs; listener preference.

## What was built (off by default)

- The page's `seam: "overlap"` mode (`src/web/player.html`, `WebPlayer(seam=...)`): a pool of three video elements, so a queued clip never evicts the prefetch or the element still sounding; the picture cuts from clip N to N+1 when N's media time reaches `duration − overlap` (N+1 starts at its own head, the same picture), with no opacity fade; an equal-power audio crossfade over the overlap (speech-safe: a clip that opens on speech comes in at once); the first clip a 150 ms fade-in. `Playable.overlap_seconds` and `Playable.speech`; the hold is the clip length minus the next clip's overlap.
- AUD-03's candidate encode (`server/audio_ceiling.py`, used by the server only with `LTX2_AUDIO_CEILING_LUFS` set): the audio padded to the video, one static never-boosting gain down to the ceiling and under −1 dBTP, measured with ffmpeg's ebur128; the measurements in `X-Audio-*` headers. `scripts/experiments/ceiling.py` applies the same module to a run's clips offline.
- `scripts/seam_check.py --seam overlap --overlap-frames 9` runs the candidate page in headless Chromium with the real `WebPlayer`.
