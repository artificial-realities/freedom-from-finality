# CLAUDE.md

Artificial Realities is an interactive generative movie platform — a continuously streaming AI-generated film whose story responds to viewer input while it plays. See [README.md](README.md) for the vision and the open problems.

The current prototype reaches that through a deterministic engine that drives **two LLM roles on two clocks** (a Director that writes one beat of a few clips per call and a slow-clock Showrunner) over a **typed world model**, and renders each clip with LTX-2.5 just in time. **The orchestration is one mechanism under exploration, not the definition of the project** — treat it as replaceable.

## Layout

```
main.py                  # play command; --config, --story, --player, --segments, --log-dir
src/
  graph/director_engine.py   # DirectorEngine — current design (graph: "director")
  agents/director.py         # one structured call per beat (BeatPlan: one action or state as 1-4 clips)
  agents/showrunner.py       # slow-clock compaction + planning (ShowrunnerUpdate)
  prompts/                   # director.*.md, showrunner.*.md
  story/                     # typed world model (world, with each entity's state), schemas, validator (per clip), context, compiler
  state/story_state.py       # StoryState — runner-facing surface shared by both engines
  models/                    # config, story (blueprint), responses (legacy views)
  i2v/                       # image-to-video backends (base, ltxv, replay)
  llm/                       # LLM backends (openai, mock for offline tests)
  playback/player.py         # Playable + Player boundary of the live loop; TerminalPlayer (ffplay + stdin)
  web/                       # WebPlayer (aiohttp: SSE stream, /input, clips, /beacon) + player.html
  eval/runner.py             # run_live (the film: just-in-time render, viewer interrupts) · run_play (terminal, turn by turn)
  ui/terminal.py             # free-text input between clips (run_play)
  util/                      # json sanitizer, langfuse, media, prompt loader, story log, timing log
tests/                       # python -m tests.run (no pytest needed); jit_sim.py: the live config under compressed time (test_jit); test_checks: the seam tools; test_replay: the compiler replay and the warm probe
scripts/steer.py             # scripted viewer: posts lines to a running web player at given segments
scripts/latency_probe.py     # seconds per clip second for one server setting; --warm 30 checks a warmed server against the baseline (+3 %)
scripts/bench_report.py      # a run's timing.jsonl against the gates; --update-readme regenerates the README's baseline table
scripts/seam_check.py        # after player changes: duplicate frames per seam from the clips; dip, swap latency, reloads in headless Chromium
scripts/audio_check.py       # after audio changes: per-clip loudness and true peak; the played mix's seam steps, clicks, holes
scripts/replay_compiler.py   # a run's Director outputs through the compiler, offline: --verify against the transcript, --diff between compilers
scripts/experiments/         # decision-record experiments: drivers, judges, arms (evaluation-only; results in docs/reviews/experiments/)
scripts/llmbench/            # LLM benchmark (evaluation only): cases from real film states, any OpenAI-compatible model, Claude judge, lockstep films, GPU-box tooling (vLLM, co-hosting); `python -m scripts.llmbench`
benchmarks/runtime/          # baseline.json: the canonical render baseline and its gates
benchmarks/llm/              # the LLM benchmark's models.yaml, cases, results (README.md)
configs/                     # director.yaml (headless) · director.live.yaml (LTX-2.5) · director.replay.yaml (replayed clips)
stories/                     # per-story folders (story.json blueprint, reference image, assets); README.md: the field guide
docs/                        # ARCHITECTURE.md · reviews/ · legacy/ · research/llm-evaluation/ (2026-10 LLM study: recommendation.md)
server/                      # LTX-2.5 inference server (runs on a GPU box; see server/README.md)
```

## Conventions

- **State & responses**: Pydantic v2 `BaseModel`. Not `TypedDict`, not raw dicts. The world model (`src/story/world.py`) is the system of record; prose is never the source of truth.
- **Agents**: async functions, not classes. They read prompt sections from `src/story/context.py` and return schema instances; they never mutate the world. Only `src/story/validator.py` mutates the world.
- **Workflow, not agent system**: no tool use, no LLM-directed control flow. The engine decides order and triggers; the LLM proposes, code validates and applies.
- **Rendering is opt-out, content is not.** The Director writes the same beats, lines and world changes whether or not anything renders (`video_enabled`). Never gate content generation on rendering flags.
- **The video model's dialect lives in one place**: `src/story/compiler.py`. Schemas do not change when the model does.
- **Structured outputs are strict**: keep `BeatPlan` and `ShowrunnerUpdate` inside OpenAI's strict subset (no free-form dicts). Enforce structure in the validator, not the schema.
- **Prompts, schemas, compiler and engine are story-agnostic.** The Lego story is one blueprint; anything story-specific (looks, anchors, truths) lives in its story folder under `stories/`. Each story is a directory with `story.json`, a reference image, and any other assets. `--story stories/lego-void` (the default).

## Running

```bash
python main.py play --config configs/director.yaml                                        # headless dev — no video or audio
python main.py play --config configs/director.yaml --player web                           # the film as text in a browser; type to steer
python main.py play --config configs/director.live.yaml --player web                      # live video in the browser (needs the LTX-2.5 server)
python main.py play --config configs/director.replay.yaml --player web                    # the player with replayed clips from logs/video, no GPU
python -m tests.run                                                                       # offline test suite (mock LLM)
```

Default to the headless config. Live runs need an LTX-2.5 server reachable at `ltxv_server_url` on a GPU box, so they are not available by default in this environment. The live film runs **on the GPU box**: `server/vast_run.sh up` rents it and starts the server, `server/vast_run.sh run` ships the working tree there, runs `main.py play --player web` next to the server and tunnels the player to `http://127.0.0.1:8765/`, `pull` fetches the logs and clips, `down` destroys the box. `--player web` serves the player at `http://127.0.0.1:8765/` (`--port`, `--host`); `--segments N` bounds a live run. Runs write a markdown transcript to `logs/` and the world model and a timing log (`timing.jsonl`: fires, renders, queue margins, stalls, viewer lines, Director calls, browser beacons) to `logs/sessions/<session>/`.

## Current constraints

- **Within-clip identity drift was the sampling recipe, not the prompts.** Every run before 2026-09-15 ran the distilled transformer with the full-model recipe (CFG 3, STG, 15 linear steps); on the correct distilled recipe (`LTX2_VARIANT=distilled`, 8 sigmas, unguided) the figure's torso, legs and ground hold through the action with no anchor, and the Director continues across segments instead of cutting every one (`docs/reviews/2026-09-15-substrate-sweep.md`). The Director wrote eyebrows, frowns and smirks and the model painted them; the blueprint now forbids facial expressions and the verification run shows plain faces. Real residual drift is a greying ground at the end of the busiest clips. Re-seeding cuts were removed on 2026-09-17: the Director writes one continuous picture (a prose cut where the story allows it, LTX-15, is still conditioned on the last clip's frames), and the renderer seeds only the first clip of a run from the reference (checked at load and at startup; the live config's `i2v_reference_fit: strict` takes only a reference at the render aspect to the pixel and resizes it whole, and refuses anything else, RUN-17; the Lego story's is `legoman-16x9.png`, a medium-shot crop of the owner's 16:9 master), which the compiler opens from the reference's `shows` (a character it does not name enters during the first clip); after a server restart the client sends the last clip's tail and the picture continues (`ltxv_restart_recovery: "window"`, D-12), falling back to the reference, with the Director told, only when the tail cannot be read. A re-seed resets costume, props and position to the reference's state (the red cap vanished at a cut on 2026-09-15; a re-entry cut on 2026-09-17 put a second figure on screen for a moment), so nothing re-seeds mid-film. A viewer's line typed while clip N plays lands at N+2, or at N+3 if it arrives after the render of N+2 has fired, with either `startup_clips` setting: the live loop starts the Director call for the next beat as soon as the beat's last clip is emitted (`plan_early`, RUN-15; `false` restores the late start) and a line typed meanwhile cancels and restarts it. `startup_clips` (was `lead_clips`) buffers only at startup (it sets the startup gate and the queue size); the steady state is `buffer_seconds` (4.7 s, what the schedule kept implicitly before RUN-03 named it). Every clip has the run's one clip shape (RUN-01, `src/i2v/shape.py`): `clip_seconds: 6` becomes 145 frames at the server's 24 fps, held 6.04 s; the Director is told that length, the engine records it, the render request carries the frames and the player holds the delivered frames, and nothing else derives a length (`i2v_duration` is gone; an old config's value maps onto `clip_seconds`). The server warms the frame counts the client's registry lists (`python -m src.i2v.shape <config>`, passed by `vast_run.sh`), reports them in `/health` `warm_frames`, and the client refuses to start without its shapes, so a mid-film compile cannot happen; extra shapes (`extra_clip_seconds`) are registered only for the X-18 experiment.
- **`ltxv_continuity_strength`** trades continuity against steering for `continue` shots. At `1.0` new prompts barely land; lower values let steering through at the cost of visual continuity.
- **The server picks the weights and the recipe with `LTX2_VARIANT`** (`server/ltx2_server.py`): `distilled` (default) is the 8-sigma unguided recipe on `transformer/`; `full` loads `transformer_full/` at 30 steps with guidance and shifting, and on 2026-09-15 gave the same identity at 3.5× the time with an extra-character artefact, so it is not used. Placement is `LTX2_OFFLOAD`: `gpu` (default) keeps everything resident (70 GB on an H100 PCIe; 12–13 s per 5 s clip and 17–23 s per 6–8 s clip, of which the 8 transformer forwards are 11–19 s, plus 1.2–1.8 s to encode; a fresh box adds 10–20 s of CPU warm-up to its first three clips); `text` offloads only the Gemma text encoder (28 s); `cpu` offloads everything (57 s). The Diffusers pack ships no prompt enhancer (it loads as `None`) and none is used by decision: prompt structure is the application's, in `src/story/compiler.py`. The server logs a per-stage breakdown (`timings:`) each turn and encodes the MP4 through ffmpeg (diffusers' PyAV path took 17–24 s per clip). `server/vast_run.sh` rents and tears down a GPU on Vast.ai (`up`, `restart` to switch any `LTX2_*` setting without re-renting, `down`); it defaults to an H100 SXM or NVL, which are cheaper and faster than the PCIe. Speed flags on the server (`LTX2_ATTN`, `LTX2_QUANT`, `LTX2_COMPILE`, `LTX2_WIDTH/HEIGHT`, `LTX2_ENCODER`, warm-up at startup) and the plan behind them: `docs/reviews/2026-09-16-real-time-plan.md`; `scripts/latency_probe.py` measures a setting.
- **Real time: the numbers live in `benchmarks/runtime/baseline.json`**, the canonical render baseline and its gates (tails, not means: render ratio p95 and max, zero stalls, a minimum queue margin); the README's table is generated from it, and `python scripts/bench_report.py logs/sessions/<id>` checks a run's `timing.jsonl` against the gates. Do not restate ×RT figures elsewhere. The frame size is one standard, 512×288 (exactly 16:9; RUN-17, D-15, GPU session 4: identity and detail held by eye against 640×352, `logs/experiments/gpu4/run17/`), for the render and the reference alike. The 2026-09-16 probes that chose the rest of the setting (fp8 + compile, then 640×352 on an H100) are in `docs/reviews/2026-09-16-real-time-plan.md` and `logs/probe/`, reconciled in review 03 §2.2. The forwards are compute-bound (compile 1.22×, fp8 1.27× on Hopper, tokens linear); the newer diffusers VAE decode needs 25–40 GB untiled and the server tiles it on demand; FlashAttention-3 refuses LTX-2's attention masks; NVENC is unavailable in Vast containers; under fp8 each clip shape compiles separately (90–170 s), so a live run wants one clip length; the MP4 through the ssh tunnel costs 1.5–4.6 s per clip, so the client belongs on the GPU box.
- **Seams (D-03; live since 2026-09-24).** The live config's `seam: "overlap"` renders 153 frames (144 new + the 9-frame window) and holds 6.0 s; the page cuts where the next clip's repeated head begins and crossfades the sound over it; the server keeps each clip under `audio_ceiling_lufs: -18` with its audio padded. `seam: "fade"` (145 frames, each file whole, a 250 ms opacity crossfade) is the way back. The render-time headroom that made room for it (RUN-14: frames converted on the GPU, YUV piped to ffmpeg, 8 x264 threads) is the server's default; the numbers are in the baseline (`docs/reviews/08_OWNER_DECISIONS.md`, BATCH_027).
- **Identity anchor**: `ltxv_anchor_strength` conditions every clip on the reference image as a guiding keyframe at `ltxv_anchor_index` (latent frames, -1 = last), on top of the index-0 condition. Off: it is not needed for identity on the correct recipe, an end anchor suppresses the closing action and a mid anchor inserts an idle beat.
- **LTX-2.5 renders all the audio**: ambient sound and the characters' lines, from the compiled prompt. There is no narrator and no external TTS (both removed on 2026-10-06, with ElevenLabs): every spoken word is a character's `dialogue`, any character may speak (no `speaks` flag), and a line is compiled as `Name says in a … voice, "line"` from the character's `voice`. Unverified on the GPU: two speakers in one clip (X-29 was skipped) and a minifigure's printed face while it speaks (the model may animate a mouth).
- **Fail-soft rendering (2026-09-23, RUN-07/RUN-09).** The previous render is known before the next clip is emitted; a failed render is retried once if it can still land in time, otherwise the world and beat roll back to before the clip and the segment is replanned from the clip before (an emit exception too); three failures in a row stop the film. `fail_soft: false` is the old skip-and-continue.
- **Cuts are the story's choice (LTX-15, D-13, 2026-09-24).** A blueprint may allow cuts (`picture.perspective.cuts`, guidance in `cutting`); the Director then may set a clip's `cut_to` (the new shot), compiled as "The view cuts to …" after the shot the picture is in, and the world tracks the current shot. Without it a cut is dropped by the validator; the Lego story stays one continuous take (D-16: GPU session 4's cuts landed 2-4 s into the clip and repainted the face in close-ups). Never on the film's first clip.
- **The blueprint is the essential story, not a script (2026-10-06).** `story.json` holds what the film is (`premise`, `question`, `engine`, `opening`, `truths`: what holds whatever the viewer does), who tells it (`storyteller`: `theme`, `tone`, `temperament`, `never`), who is in it (`locations`, `cast`) and how it looks (`picture`: `style`, `anchor`, `reference` with the image and what it `shows`, `perspective`). Empty fields add no prompt text. There is no time axis beyond the opening: the Showrunner writes the arc, and an authored sequence would pull the film away from the viewer as the scene card did (D-01). Both roles read the film block and the truths; only the Showrunner reads `opening`.
- **The cast is the story's policy, not a global lock (2026-09-23).** A blueprint names its protagonist (kept single and in the story by the validator), characters with `who`, `wants`, `nature`, `voice`, `look`, `look_short` and a starting state, supporting characters with entrance conditions (the Showrunner decides when, the Director stages), what kind of characters the film may introduce beyond the cast (`cast.newcomers`, empty for none; a newcomer is registered once with its look, who it is, voice and state) and its `perspective` (default and permitted switches, declared per beat in `BeatPlan.perspective`). The Lego story is the only story and exercises all of it: Lego Man, the Spaceman (must appear, when a bit first fails badly), newcomers from any LEGO theme, a first-person switch through binoculars; one location.
- **The frame observer and the evaluation tooling were removed on 2026-09-16.** The observer (a vision check of every rendered clip that showed the Director a "Picture" section and forced a cut on drift) measured a drift the recipe fix had already removed, its forced cut never fired in any run, and its rubric misread framing; the scripted scenarios, the style sweep and the `--scenario` driver went with it. The project is an MVP of one thing: a film that plays and takes steering, not a research harness.
- **The Showrunner never blocks a segment (2026-09-17).** Its update lands at the first plan (the next Director call) that finds the task finished, since clips inside a beat are emitted without a plan; a running task is left alone. Runs are at least `showrunner_min_gap` segments apart and one at a time; held triggers are noted in the transcript, and a held `scene_done`/`needs_replan` is remembered until a replan run takes it (2026-09-23). A run is triggered at the plan and spawned after the beat's first clip is applied, so its snapshot includes that clip. No code measures stagnation (2026-10-15): the similarity check, the stagnation ladder and the forced scene end at `scene_seconds` were removed after the 2026-10-14 luna film, in which the gate said "no pacing pressure" on every beat of a ball-passing loop and the Showrunner deferred to its timer; both roles judge from what they read whether the film is going in circles, the Showrunner on every compaction pass, and the plan shows them how long the scene has run against `scene_seconds`. The authority rule, in both system prompts: while a viewer's direction is active the Director outranks the scene card, which is the menu for the quiet stretches; a direction is active for `viewer_momentum_seconds` (90) of film or until the next line, the Director does not see the card's candidate beats meanwhile, and only a card whose Showrunner trigger arose after the line clears it (D-01 on X-07/X-08, 2026-09-23). Before this, a synchronous join at the next segment stalled the pipeline 2-8 s on a fifth of the segments (`docs/reviews/2026-09-17-continuity-and-buffering.md`).
- **The Director writes beats and the loop renders just in time (2026-09-17; run live once, session A on 2026-09-18 at `265e9fd`: 64 clips, `logs/live-box/director-ltxv_live_20260918_145552`).** A `BeatPlan` is one action or state as 1-4 clips (`max_clips_per_beat`), each clip with its own action, end state and entity ops, so the world advances clip by clip and a beat can be cut short after any clip. The engine emits clips with no LLM call; the Director is called when the beat ends or when the viewer speaks (the rest of the beat is dropped, a Director call in flight is cancelled and restarted with the line, and a line that arrives after the answer was written but before it played is joined to it and planned once). A beat that answers a line has at most two clips (`answer_max_clips`), and a deferred request is delivered by name (`BeatPlan.delivered_request`, its segment). The live loop fires each render its estimate plus `buffer_seconds` before the clip is due on air and asks for the next beat only when needed, listening for the viewer in between; with the renderer under real time a line lands two clips after it is typed. The Director's call size is on the per-clip critical path. Since 2026-10-14 both roles are gpt-5.6-luna at no reasoning (`director_model`, `showrunner_model`, `*_reasoning_effort: "none"`): luna beat gpt-5.4-mini as Director under both judges and produced the best films, and won 22/22 vs gpt-4.1 as Showrunner; cost $0.50/film-hour (was $3.88). The evaluation data is in `docs/research/llm-evaluation/` and `benchmarks/llm/` (gitignored for now; the harness is `scripts/llmbench/`). Every entity carries its `state` in the world model as one line of prose (a character's pose, place and doing; a prop's place, condition and who has it; `holder`, `posture`, `activity`, `position` and `status` folded into it on 2026-10-15), scene length is counted in story seconds (`scene_seconds`), the Showrunner's notes live in the user prompt so the system prompt stays cached, and the compiler sends the full style and looks only on the opening clip (`picture.anchor` and `look_short` from the blueprint afterwards); an entity that enters the picture (introduced, or back after an absence) is described on that clip before the action and never listed as already on screen, and the camera is a clause ("the camera remains static", "the camera makes a slow push-in …"). Viewer momentum and the per-story folders (`1de34a0`) came after session A and have not run live.
- **The previous four-role engine was deleted on 2026-09-08** after a 30-turn A/B and a 180-segment run (`docs/reviews/`). Its design is documented under `docs/legacy/` for reference only.
